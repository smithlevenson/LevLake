# CONTRIBUTING.md

# Contributing

This repository is maintained by the Levenson family.

Human and AI contributors should follow the same workflow.

---

# Before Coding

Read:

1. README.md
2. docs/ai-context.md
3. docs/current-state.md
4. docs/work-queue.md

Review any related architecture decisions before making significant changes.

---

# During Development

- Make focused changes.
- Avoid unrelated refactoring.
- Preserve the design language.
- Keep code readable.
- Prefer simple solutions.

---

# Documentation

If your work changes:

- architecture
- workflow
- UI principles
- project direction

update the appropriate documentation.

---

# Before Committing

Verify:

- Application starts
- Feature works
- No obvious regressions
- Documentation is current

---

# Commit Messages

Use descriptive commit messages.

Examples:

Add reservation approval prototype

Improve Lake Brief layout

Refactor calendar rendering

---

# Architectural Changes

Significant architectural decisions should also be recorded in:

docs/decisions.md

---

# Goal

Every commit should leave the repository easier to understand than it was before.
